# 笔记详情抓取与列表定位设计

## 目标

在博主主页采集结果中，用户可以点击筛选后的笔记快速打开对应的详情悬浮层；用户也可以一次性按当前筛选顺序逐条打开详情悬浮层，读取正文和第一张主图 URL，并把结果导出到 Excel 或导入飞书。

## 已确认的页面结构

小红书主页点击笔记后仍停留在当前页面，详情内容位于悬浮层中：

- `.note-detail-mask[note-id]`：详情遮罩和当前笔记 ID
- `#detail-title`：标题
- `#detail-desc .note-text`：正文文本
- `#noteContainer .media-container img`：详情图片，第一张作为封面 URL
- `.close-circle` / `.close-box`：关闭详情

这些选择器属于页面 DOM，代码必须保留可见性检查和无结果处理，不能依赖内部 API。主页卡片打开详情时不使用脚本合成点击，而由 content script 计算卡片坐标，background 通过 `chrome.debugger` 的 CDP `Input.dispatchMouseEvent` 发送鼠标输入。

## 交互与数据流

1. 列表项保存笔记 ID，并保留现有原文链接。
2. 点击列表项时，在主页中找到同一笔记卡片，滚动到卡片并触发卡片点击；详情悬浮层打开后保持当前页面位置。
3. 点击“抓取正文”后，按当前筛选和排序后的列表顺序串行处理：定位卡片、点击、等待匹配的 `note-id` 详情层、读取正文和第一张图片 URL、关闭详情层。
4. 每行记录抓取状态；单条失败只标记该行并继续下一条，遇到登录或验证码等页面异常时停止整批任务。
5. Excel 增加 `正文`、`封面链接` 两列；飞书增加同名字段，并要求目标表存在这两个字段。

## 风险边界

- 不请求小红书内部接口，不绕过登录、验证码或访问限制。
- 真实点击需要 Manifest V3 的 `debugger` 权限；每次操作只短暂 attach 当前标签页，发送一次点击后立即 detach。
- 不下载图片文件，只保存浏览器页面已公开展示的图片 URL。
- 不并发打开详情；抓取任务只能由用户在面板中启动，并支持停止。
- 图片 URL 可能带签名或过期，导出值按页面当时提供的 URL 保存。

## 验证

- Node 单元测试覆盖笔记 ID、正文节点合并和第一张图片 URL 选择。
- `node --check` 检查三个 JavaScript 运行文件。
- 手动验证主页列表点击定位、批量抓取、Excel 字段和飞书字段。
